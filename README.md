## 検索APIのカテゴリー指定

`GET /api/search` は `categories=食品&categories=飲料` の繰り返しクエリで、いずれかのカテゴリーに該当する商品を検索できます。キーワード・価格・在庫条件とはANDで組み合わせます。

- `categories` と `category` がともに未指定・空文字のみの場合は、カテゴリーの絞り込みを行いません。
- 従来の `category=食品` も使用できます。
- 空文字以外の `categories` がある場合は、`category` より優先します。
- 該当件数 `total` は取得上限 `limit` によらず、全該当件数を返します。

検索APIのテストは、リポジトリ直下で次を実行します。FastAPIとhttpxが必要です。環境変数ファイルや実DBは使用せず、SQLiteのインメモリDBで検証します。

```powershell
python -B -m unittest discover -s backend/tests -v
```

## 検索結果の並び替え（STEP 2-2 A〜C）

`GET /api/search` の既存条件とレスポンス `{ total, results }` は維持します。
並び替えは取得上限を適用する前にDBで行います。件数はランキング用JOINの影響を受けません。

| パラメーター | 値 | 意味 |
| --- | --- | --- |
| `sort` | `price_asc` | 価格昇順。同価格は評価済み優先→ベイズ評価降順→有効口コミ件数降順→商品ID昇順 |
| `sort` | `popular` | 指定期間の購入数量合計降順、同数量は商品ID昇順 |
| `sort` | `rating` | 有効口コミから計算するベイズ評価順 |
| `sort` | 未指定 | 互換性のため従来の `sales_count DESC, product_id ASC` |
| `popularity_period` | `weekly` / `monthly` / `yearly` / `all` | 人気順の期間。既定値は `monthly` |
| `scene` | 送別・誕生日・母の日・お歳暮・お中元・結婚祝い・父の日・出産祝い | 同名のproduct_scenes.scene_tagで絞り込み。空・未指定は全シーン |

不正なsort・期間は422を返します。期間は人気順以外では並び順に使いません。
通常検索UIは `sort=popular&popularity_period=monthly` を明示して送ります。
旧APIの個包装・価格帯パラメーターは互換性のため維持します。取引先専用タブ・フォームは画面から撤去しました。

### 人気順の期間と基準日

人気度は `orders.order_id = order_items.order_id` で結合し、
`order_items.product_id` ごとに集計した **`SUM(order_items.quantity)`** です。
注文件数ではありません。販売実績のない商品は数量0として残します。
キャンセル・返品ステータスがないため、その除外処理は行いません。

デモ基準日は `backend/main.py` の `DEMO_REFERENCE_DATE = date(2026, 6, 30)` です。
システム日付は変更せず、人気順の集計だけに使用します。
本番で当日に追従させる際は、タイムゾーンを決めたうえで基準日の取得を
リクエスト時の現在日付へ切り替えてください。APIから任意の日付は指定できません。

| UI | 内部値 | ordered_atの開始（以上） | 終了（未満） |
| --- | --- | --- | --- |
| 週間 | `weekly` | 2026-06-24 00:00:00 | 2026-07-01 00:00:00 |
| 月間 | `monthly` | 2026-06-01 00:00:00 | 2026-07-01 00:00:00 |
| 年間 | `yearly` | 2026-01-01 00:00:00 | 2026-07-01 00:00:00 |
| 全期間（累計） | `all` | 制限なし | 制限なし |

月間は暦月、年間は暦年です。直近30日・365日の定義ではありません。
終了日の翌日未満で比較し、6月30日の注文をすべて含めます。
DATETIMEの保存時刻をそのまま比較するため、日付境界は保存データの時刻基準に従います。

### 価格順の同価格時の扱い

価格を最優先し、同価格の商品の間だけ評価済みを優先します。
続いてベイズ評価スコア降順、有効口コミ件数降順、商品ID昇順で表示します。
未評価商品が安い場合は、高い評価済み商品より前に表示します。
評価済み判定・スコア・件数は以下の評価順と同じ集計を共用し、
`products.rating`・`products.review_count` は順位計算に使いません。
価格順も有効口コミの集計が必要になるため、従来の価格だけのソートより処理量が増えます。
評価集計のSQLは共用し、人気順・sort未指定時には実行しません。

### ベイズ平均による評価順

`score = (v × R + m × C) / (v + m)`、補正係数は `BAYES_PRIOR_WEIGHT = 10` です。

- 有効口コミ：`reviews.rating BETWEEN 1 AND 5` かつ既存商品に紐付くもの。
- v：商品別の有効口コミ件数、R：商品別の有効口コミ平均。
- C：全既存商品の有効口コミをまとめた平均。検索条件や在庫では限定しません。
- Cはリクエスト時に集計し、調査時の4.2021を固定値として使いません。
- 評価済みを優先し、スコア降順→有効口コミ件数降順→商品ID昇順で表示します。
- NULL・範囲外評価は集計から除外し、未評価商品は末尾に商品ID昇順で表示します。
- 全体に有効口コミがない場合も商品を除外せず、商品ID昇順になります。

m=10はgiftia_t105の実データ調査後に採用した値です。
調査時の商品数8,000、有効口コミ24,752、評価済み商品4,296、0件商品3,704、
件数中央値1件、1〜5件商品3,358という分布を踏まえ、少件数商品の過大評価を抑えます。
商品テーブルとの件数不一致1商品・平均不一致1,265商品も確認されているため、
ランキングには `products.rating`・`products.review_count` を使いません。
カード・商品詳細に表示する従来の評価値は変更せず、保存データの補正も行いません。

### フロントエンドの動作

- 初回は検索ボタンで取得し、その後の並び替え・期間変更で直前の検索条件を保持して再検索します。
- フォームの未適用の編集は、自動再検索に含めません。反映には検索ボタンを押します。
- 連続リクエストは最新の結果だけを表示します。
- 条件クリアで月間人気順へ戻し、自動再検索用の条件もクリアします。
- シンプル検索の並び替えは人気順・評価順・価格順です。おすすめ順は候補に含めず、新着順は準備中として選択不可です。
- おすすめ検索は独立したモードとして表示しますが、検索実行は準備中です。
- シーンは実DBで同名タグを確認した8種類に対応します。好み・年代・性別はUIで選択できますが、検索結果への反映は今後対応予定です。

## 2モードの検索画面

検索画面最上部の「おすすめ検索」「シンプル検索」で直接切り替えます。
初期表示はシンプル検索です。「いまの検索」「取引先へのお礼」の旧タブと、
取引先専用フォーム・専用検索処理は撤去しました。「取引先へのお礼」はシーンとして残します。

条件はキーワード→シーン→ギフトポリシー（おすすめ検索の対象シーンのみ）→
贈る相手の年代→贈る相手の性別→カテゴリー→好み→価格帯の順に表示します。
ギフトポリシーは「王道（classic）」「ユニーク（unique）」の単一選択で、
再クリックで解除できます。送別・取引先へのお礼以外のシーンへの変更、
シーンの解除、条件クリアでポリシーも解除します。

`frontend/lib/recommendationUi.ts` に、おすすめ順用の必須入力判定を分離しています。
おすすめ検索ではシーンが必須で、送別・取引先へのお礼ではポリシーも必須です。
シンプル検索ではポリシーは非表示で、APIに送信しません。

おすすめ検索は準備中です。必須不足のガイドを表示し、必須項目を満たしても
検索ボタン・submitの両方でAPI呼び出しを止めます。ランキング・理由表示は行いません。
年代・性別・好みは両モードで選択可能です。選択時はタグの色が変わります。
「今後対応予定」と明示し、APIへは送信しません。データ整備後にAPI連携を追加してください。
ギフトポリシーのランキング用データも未整備です。

モード変更時はキーワード・シーン・年代・性別・カテゴリー・好み・価格帯を保持します。
ポリシーもおすすめ検索用として保持しますが、対象外シーンへの変更・シーン解除・条件クリアで解除します。
並び替えと期間も保持します。結果・エラー・直前の検索条件は消去し、処理中の古い応答を無効化します。
モード変更では自動検索しません。シンプル検索に戻った後は検索ボタンで再検索してください。

### シーンの対応関係

Workbenchのgiftia_t105集計結果により、送別・誕生日・母の日・お歳暮・お中元・
結婚祝い・父の日・出産祝いの8種類はUIと同名タグがあることを確認しました。
対応済みシーンをsceneパラメーターで送信し、product_scenesへのEXISTS条件を
件数取得・商品取得に共通で適用します。値はプレースホルダーで渡します。
タグが重複していても商品は重複せず、カテゴリー・キーワード・価格・在庫条件とANDで組み合わせます。
シーン未指定の既存APIと人気順・評価順・価格順は維持します。不正なsceneは422です。

DBには「お礼」が3,290商品ありますが、「取引先へのお礼」との意味の一致は未確認です。
「お祝い」も同名タグがありません。両者を勝手に読み替えず、シンプル検索では
選択肢を表示したまま新規選択を無効化しています。おすすめ検索ではどちらも選択できます。
おすすめ検索から未対応シーンを保持してシンプル検索へ戻った場合は案内を表示して検索を止めます。
そのタグを再クリックして解除するか、対応済みシーンを選ぶと検索できます。
「お礼」や下位のお祝いシーンへの対応付けは、別途仕様を決めてから追加してください。

確認に使用した集計SQL（実行は読み取りのみ）：

```sql
SELECT scene_tag, COUNT(DISTINCT product_id) AS product_count
FROM giftia_t105.product_scenes
GROUP BY scene_tag
ORDER BY scene_tag;
```
